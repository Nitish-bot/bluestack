# Quasar Glossary

**Official:** [Accounts and Validation](https://quasar-lang.com/docs/core-concepts/accounts-and-validation) · [Pod Types](https://quasar-lang.com/docs/zero-copy/pod-types) · [official-docs-index.md](official-docs-index.md)

Terminology discipline for Quasar Solana programs. When a user or spec uses Anchor vocabulary, map it here before writing code.

## Core concepts

| Quasar term | Definition | Anchor equivalent |
|-------------|------------|-------------------|
| **Zero-copy (ZC)** | Account data accessed via pointer cast to `#[repr(C)]` companion struct; no deserialize step | Borsh deserialize into heap/stack struct |
| **Pod type** | `#[repr(C)]` type with alignment 1 (`PodU64`, `Address`, etc.) safe to cast from raw bytes | N/A — Anchor uses native Rust types after deserialize |
| **Discriminator** | Explicit byte prefix on accounts and instructions, set by the author | Implicit 8-byte sighash (accounts) or 8-byte ix prefix |
| **Companion struct** | Generated `FooInner` / ZC layout backing `Account<Foo>` | Deserialized `Account<Foo>` inner data |
| **Ctx\<T\>** | Instruction context: parsed `T` accounts, `T::Bumps`, program id, ix data | `Context<'info, T>` with `accounts`, `bumps`, `remaining_accounts` |
| **Address** | `solana_address::Address` — 32-byte pubkey | `Pubkey` |
| **AccountView** | Low-level runtime account handle from SVM input buffer | `AccountInfo` |
| **no_alloc default** | Entrypoint sets heap cursor past end; allocation fails unless `heap` ix | Heap always available via `solana_program::entrypoint` |

## Account wrappers

| Type | Role |
|------|------|
| `Account<T>` | Typed, validated view; writable via `#[account(mut)]` on the field — not `&'info mut Account<T>` |
| `Signer` | Validates transaction signer bit; writable via `#[account(mut)]` — not `&'info Signer` |
| `UncheckedAccount` | No type/owner validation — use with explicit `constraint` or manual checks |
| `Program<T>` | Validates executable account matches program ID (`System`, `Token`, custom) |
| `InterfaceAccount<T>` | Accepts multiple valid owners (e.g. SPL Token + Token-2022) |
| `Sysvar<T>` | Validates sysvar account (`Rent`, `Clock`) |
| `OptionAccount<T>` | Optional trailing account in struct |

## Macros

| Macro | Purpose |
|-------|---------|
| `#[program]` | Module containing instruction handlers; generates dispatch |
| `#[instruction(discriminator = N)]` | Marks handler; sets ix discriminator bytes |
| `#[instruction(discriminator = N, heap)]` | Enables heap for this instruction arm |
| `#[account(discriminator = N)]` | Defines on-chain account layout + validation |
| `#[account(..., set_inner)]` | Generates `set_inner(Inner)` for init paths |
| `#[seeds(...)]` on account type | `HasSeeds` prefix + dynamic arg count; use `address = Type::seeds(...)` in `#[account]` (constraint syntax, not a method on the type) |
| `#[derive(Seeds)]` helper struct | Lamport PDA without `Account<T>` state; `VaultPda::seeds(user.address())` |
| `{field}_seeds(&bumps)` on Accounts struct | CPI signer seeds as `[Seed; N]` (generated by `#[derive(Accounts)]`) |
| `#[derive(Accounts)]` | Account validation struct for an instruction |
| `#[event(discriminator = N)]` | Event struct for `emit!` / `emit_cpi!` |
| `#[error_code]` | Custom program error enum |
| `declare_program!` | Compile-time CPI module from IDL JSON |

## Pod integer types

| Type | Storage | Notes |
|------|---------|-------|
| `PodU64` | `[u8; 8]` | Use `checked_add` for balances; `+` wraps in release |
| `PodU32`, `PodU16`, `PodU8` | byte arrays | Same arithmetic semantics |
| `PodI64`, etc. | signed variants | Same overflow rules |
| `PodBool` | 1 byte | |
| `PodString<N, PFX>` | Fixed-capacity string in account | PFX ∈ {1,2,4,8}; dynamic region |
| `PodVec<T, N>` | Fixed-capacity vec in account | Element type must be Pod |

## CPI vocabulary

| Term | Meaning |
|------|---------|
| **CpiCall** | Builder returned by `.transfer()`, `.invoke_signed()`, etc.; const-generic account count |
| **TokenCpi** | Extension trait on `Program<TokenProgram>` for SPL instructions |
| **Seed** | PDA signer seed for `invoke_signed` |
| **DynCpiCall** | Dynamic-account-count CPI (higher CU) |

## Reserved values

- **0xFF** — borrow-state sentinel in account header (framework internal)
- **All-zero discriminator** — banned at compile time for accounts and instructions
- Instruction discriminators within a program must share the **same byte length** and be **pairwise unique**

## Scenario: naming "authority"

In Quasar docs and code, **authority** may mean:

1. **Signer** — transaction signer matching a stored `Address` field (`has_one(authority)`)
2. **Token authority** — owner/delegate on an SPL token account (`token(..., authority = escrow, ...)`)
3. **Mint authority** — can mint tokens (`mint::authority = admin`)

Always specify which authority when designing constraints.

## Scenario: "init" vs "init(idempotent)"

- **`init`** — account must be empty (system program owned, zero lamports/data); creates account
- **`init(idempotent)`** — creates if missing, validates if present; use for ATAs and idempotent flows (replaces Anchor `init_if_needed`)

Stress-test: calling `init(idempotent)` twice in one transaction — second call must validate existing layout, not recreate.
